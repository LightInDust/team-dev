Keep the user in Codex on the Mac. Astra coordinates and accepts the whole task, local OMP DeepSeek implements, and native Sol independently reviews. Remote targets need SSH, Git and their existing test environment; do not install OMP or copy model credentials there. Use `scripts/team_dev.py`, profile `codex-ds`, selector `opencode-ds/deepseek-v4.1-flash`. Credentials stay in the local private configuration.

## Choose the applicable guidance

team-dev owns dispatch, recovery, review and closeout for this workflow. [Superpowers adaptation](references/superpowers-adaptation.md) supplies focused handoffs and review practices inside these stages, not another agent pipeline. Do not import extra reviewers, automatic commits/pushes, workspace deletion, five repair rounds or instructions to waive unmet acceptance. The current tool schema and user authorization govern routing and actions. Do not impose three models on unrelated small edits. For a plan-only request, deliver the plan without starting a worker.

## Execute one bounded slice

1. Inspect project instructions and the actual Git root/target state; preserve dirty work. Choose exact source/context files, allowed changes and target test argv. For SSH include the authorized alias and absolute Git root. Snapshot mode is implemented; direct SSH editing and non-Git targets remain manual workflows, not tested helper features.
2. Fix the observable outcome, real interfaces and acceptance before delegation. Give DS one independently testable executable layer; sequence shared-file changes from the latest baseline. Keep later slices in the overall plan without allowing DS to drop prepared requirements. New runners/renderers consuming existing components are integration work: set `task_type: integration`, capture authoritative producers/consumers and exact fields, dimensions, units, signatures and return shapes in `interface_contracts`, and declare real cross-component `integration_test_commands`. Missing context is a blocker. DS does not dispatch nested agents.
3. Explicitly select `worker_bash_mode` before `prepare`: use `declared_tests_only` when Bash is restricted to declared tests; prose constraints alone do not enable the gate. Select `worker_thinking` (`low`, `high`, `max`) with an `effort_assessment`; prefer low for clear fixed interfaces, high for bounded coupled reasoning, max only after decomposition leaves genuinely hard reasoning. Use `budget_mode: auto`; `policy --task` previews it. Explicit custom budgets and new guidance selections belong before `prepare`. Prepared/resumed tasks keep frozen policies. Sol remains max independently.
4. `prepare` captures selected files, including dirty content. Before `start` launches local OMP RPC, [compare the frozen Bash mode with the task restriction](references/task-contract.md#exact-bash-mode); resolve an omission through a fresh preparation, never a frozen-run edit. Inspect `status` and actual tool evidence. Use [the first-test checkpoint](references/task-contract.md#first-declared-test-checkpoint) to distinguish command activity from a real exercised boundary and to detect repeated inspection without executable progress. Count earlier steering toward the same single intervention; useful investigation and active tests require their own evidence. Plan the first declared test early, then finish required checks and the ledger within the frozen closeout window. Streaming analysis, repeated edits or steering ACKs do not renew budgets or prove completion. Preserve prior errors even if later text or a candidate appears.
5. Inspect the candidate, process evidence and complete acceptance ledger before `propose` / `apply`. Each original clause needs its implementation location, actual verification evidence and remaining blocker. Distinguish retained tests, coordinator checks, source inspection and missing evidence; manual success cannot replace a required regression test. Numeric/result-label claims must agree with bound saved outputs. Baseline conflicts require a fresh snapshot, never forced overwrite. The helper does not commit, push or deploy.
6. Run `test` with the exact declared commands in the target environment and read full saved logs, actual counts, failures and skips. Local worker tests do not replace target tests. Missing dependencies are NOT VERIFIED; do not fabricate a runner/package, switch interpreters or use direct `sys.modules` stubs. Real modules and integration boundaries must be exercised. Required-mode dependency failures must fail in every relevant module; all-skipped tests are not functional acceptance. Saved-image inspection is separate from numeric/unit correctness and must state actual coverage.
7. Explicitly dispatch native `gpt-5.6-sol` / `max` with `fork_turns: "none"` and a finite review handoff. Name one lifecycle coordinator by exact agent ID, normally Astra; only that owner steers recovery, interrupts, reassigns or replaces agents. Reviewers report blockers without controlling siblings. Save the actual accepted dispatch, immediately validate/generate exact provenance fields with `review_handoff.py template`, and give them to the reviewer. Supply original requirements, target/run identity, candidate/diff, tests, process binding and known gaps. For normal `record-review`, also supply the exact top-level `fingerprint` from matching applied/test records; `candidate_fingerprint` or a source-manifest hash cannot replace it. The template emits provenance metadata only; use the normal-review field checklist in the reference. The reviewer cannot access credentials or edit target code. Requested routing is not verified backend identity; actual model/effort remain unknown without supported runtime evidence. Reused reviewers retain original spawn evidence. If the requested route is unavailable, disclose it rather than substituting.
8. Fix confirmed findings from the current target, usually at most two fix rounds before reassessment. Scoped re-review must retain unresolved findings and inspect affected interfaces; a current acceptance blocker outside the fix hunk still blocks. Record the real PASS with `record-review`, check its successful terminal exit, then `finalize` and check that result before dependent work; [serial awaiting alone does not stop on failure](references/reviewer-provenance.md#exit-gated-dependent-steps). For an independently completed takeover, preserve the failed run and use a separate hash-bound completion receipt through `review_handoff.py receipt` after Astra acceptance. Its writer validates review/provenance only, not science or the coordinator's declarations. Missing required acceptance remains incomplete even when helper gates pass.

## Invariants during work and recovery

- Keep source deletions explicit in `allowed_deletions`. Use owned `TemporaryDirectory` scope for disposable fixtures and all consumers, including manual checks; no recursive shell cleanup. Preserve existing caches and uncertain scratch, disclose ownership/cleanup limits. Snapshot guards observe selected changes after they happen and are not a security boundary or host-wide cleanup proof.
- Copy an exact prepared test invocation arguments object in strict mode, using the `T#.logged` reference for worker acceptance tests regardless of expected output length (the catalog still permits `T#.direct`; new tasks use it only under an explicit coordinator exception with the evidence limitation recorded). Native read/grep/glob inspect; edit/write change allowed source; Bash runs only declared tests. Bytecode guards do not authorize probes or prevent explicit compilation. Preserve full logs and exit status; no live output filters, altered log envelopes or hidden repair commands. Refer to the specialized routing rules above when needed.
- For async Bash, track every tool-call/job generation, wait for structured completion and inspect actual exit/logs before dependent work. An ACK, tool-end, agent-end, interrupt notice or context-manager syntax does not prove successful execution or cleanup. OMP can reuse job IDs; old results cannot close new invocations.
- Preserve failed, cancelled and timed-out attempts as such. Diagnose stop trigger separately from earlier provider/stream errors. HTTP rejection is not repaired by more reasoning or time. Inspect preserved candidates before repeating work. At most one coordinator recovery for an unchanged deliverable; a fresh strict-gate run consumes that allowance. Strict-gate attempts never resume in place. After recovery fails, decompose or disclose Astra takeover with independent review. Verify worker exit before conflicting takeover; do not redispatch after takeover begins.
- Review the full process evidence, including prevented denials, unsupported command coverage and resource disposition. Copy the entire nested `process-evidence` binding into the review; a scalar subset is invalid. Preserve rejected reviews and save corrections separately. Count actual invocations and results rather than worker self-reports. A code PASS does not erase process violations.
- Keep remote identity, target HEAD and selected content bindings current. SSH command connections use `ClearAllForwardings=yes`; task keepalive is frozen without changing aliases/tunnels. Remote tests need existing GNU `timeout`. Lost SSH implies unknown outcome, and cancelling local OMP does not cancel arbitrary remote jobs. Source capture failure is a preparation failure, not a model failure.
- Reuse unchanged accepted evidence only with matching source/input/output identity and scope. A new concrete contradiction reopens the affected conclusion. Do not regenerate frozen experiments to improve a report, rewrite failed history, equate scientific correctness with software tests, or claim sampled visuals cover every full-resolution image.

Deliver changed paths, observed tests, actual Sol findings, routing evidence, scratch disposition and unresolved limits. Freeze the reviewed candidate; later changes invalidate affected acceptance. [OMP-native capabilities and reuse findings](references/reuse-research.md) are optional alternatives, not extra mandatory stages.
