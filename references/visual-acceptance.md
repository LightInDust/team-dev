# Acceptance for rendered artifacts

Use this when the deliverable is a chart, image sheet, report figure or viewer. A passing renderer unit test and valid PNG files do not prove that required labels fit the exported canvas or that a viewer can interpret them.

Before dispatch, use the existing `acceptance`, `constraints` and exact `test_commands` fields to fix:

- The input identity and permitted computation: distinguish rendering frozen inputs from rerunning an experiment, fitting a transform or recalculating scores. Preserve input hashes and immutable scientific results. If inputs are excluded from the worker snapshot, require coordinator-side target rendering; report unverified coverage until that happens.
- Expected output inventory, final dimensions/DPI, all layout classes and the densest/longest-label case, including declared empty, missing-result and failure cards. Those branches need their own text/layout checks and saved-output inspection; successful main plots do not cover them. Preserve an expected missing result as such, without fabricating scientific data; an unexpected missing required input remains an error. For a small finite set such as eleven requested images, exercise the whole set. Bind the renderer, test source, input-manifest reference, generated output hashes and inspection receipt to the reviewed candidate.
- The viewer contract: branch names, units, comparison direction, left/right and row/column/projection meaning where applicable, and required capture dates/source labels. Astra maps the user's requested comparison to source keys and display labels before delegation; an ablation is not a baseline merely because it is available. Keep coordinator interpretation errors separate from worker implementation defects. Confirm domain terminology from context. For example, `terminal` can refer to a final reconstruction, so mechanically translating it as a computer terminal can mislead; do not globally prohibit that translation in unrelated software contexts. Internal keys can remain unchanged while display labels become clear.

## Preflight real inputs and validation rules

Inspect the actual producer or frozen input manifest before designing validators and fixtures. Check documented keys, shapes, units and finite/range requirements against the requested inputs. Trace rejection rules to the contract or an established invariant: a name such as `zoom` does not by itself require that its window be contained in `full`; a reference window may legitimately include context margins. Do not turn an unsupported assumption into a negative test, clamp the inputs to satisfy it, or recompute scientific data. If the contract and observed inputs conflict, report the discrepancy for Astra to resolve before claiming acceptance.

Bind each used source to its complete declared identity and frozen hash, not only its basename: different runs/captures can contain identically named RGB files. Resolve paths on the owning host under the declared source root and alias policy, or use an explicit recorded mapping for local copies; do not resolve remote paths as local ones. A final before/after hash mismatch or a failed required layout check must raise an error/nonzero result and prevent a successful completion receipt, rather than merely writing a false metadata flag. Preserve diagnostic artifacts as failed evidence. The coordinator must inspect these results; the helper cannot infer arbitrary renderer metadata semantics.

As soon as the candidate exposes its public rendering entrypoint, exercise that entrypoint with the authorized frozen inputs in a disposable or separately versioned output directory, before spending a repair round on synthetic-only success. Follow the original computation permissions; input inspection does not authorize a new experiment or producer rerun. For a small finite set, cover every requested input, including legal edge cases. Bind the public invocation, input identity, output inventory and result to the candidate. A private helper or bypass of a failing validator can aid diagnosis but cannot establish public-path acceptance. If the real inputs/runtime are unavailable, retain NOT VERIFIED and the specific blocker instead of substituting synthetic evidence.

## Scientific source pixels and overlays

Resolve coordinate semantics before layout breadth: original versus normalized units, full-image versus crop frame, axis direction, pixel centers and half-open validity are separate contract choices. Include literal asymmetric points outside the unit square when the source uses original pixels, so a fixture cannot silently share the renderer's mistaken normalization. Test any authorized crop/display transform against independent expected positions; retain the original source coordinates. Follow the [first interface check](producer-consumer-contract.md#first-executable-interface-check) to bind this to the actual producer or immutable archived evidence.

For raw RGB/depth/mask images used as scientific evidence with pixel-coordinate overlays, explicitly disable smoothing in every original/overlay image artist: use `imshow(..., interpolation="nearest", resample=False)` for the raster export template, with declared origin, extent, aspect and matching limits. Do not let global `rcParams`, a style sheet or a later `set_data`/artist replacement silently change that policy. This applies when the contract requires original pixels; a separately authorized resampling/visualization transform must be declared and reviewed, not disguised as raw source data.

Test the actual returned `AxesImage` properties (`get_interpolation()`, `get_resample()`, `origin`, extent) under a deliberately conflicting `rc_context`, not just the presence of a keyword in source. Check each original/overlay panel's actual RGB/mask array and display properties against the independent fixture and contract, along with actual overlay artist UV coordinates, including asymmetric pixels and boundary/center conventions. Two panels agreeing with each other, or a receipt reporting `layout_pass`, cannot replace those independent observations. Inspect the saved output at final DPI. Nearest display prevents smoothing but does not prove one output pixel per sensor pixel, preserve all detail under downscaling, or establish scientific/physical correctness; keep the original-resolution source available when that distinction matters. If the display policy changes the saved evidence, regenerate affected outputs and retain old versions; a label-only test correction does not require rerunning experiments.

For deterministic raster sheets, derive the overlay's permitted pixel support from the contract's center convention, display radius, strokes and rasterization rule, independently of renderer constants. Compare the reopened output to the expected crop/resampling outside that exact permitted region, and separately check required marker geometry/colors inside it. A generously enlarged exclusion mask can hide an oversized halo and overwritten source pixels; for example, a radius-10 mask cannot establish a radius-6 contract. Use asymmetric source pixels, fractional centers and edge cases that expose such overdraw. Any rasterization allowance needs a stated basis; do not expand the mask to fit the implementation or copy the example radii into unrelated tasks.

Image extent and the final displayed axes limits are separate. Adding overlay points can expand the view through autoscaling while `AxesImage.get_extent()` remains correct; this can create white borders or different framing between an original and its overlay. See Matplotlib's [extent explanation](https://matplotlib.org/3.10.6/users/explain/artists/imshow_extent.html) and [autoscale controls](https://matplotlib.org/stable/users/explain/axes/autoscale.html). For a contract that fixes the full original pixel frame, explicitly set both limits to that frame and disable autoscale; verify again after all artists and final layout/draw. With upper-origin integer-centred pixels, a typical frame is x=(-0.5, width-0.5), y=(height-0.5, -0.5); use the actual declared convention for other coordinates, crops or authorized zooms.

Include populated overlays with valid points close to each relevant boundary, especially fractional points in the last half-pixel interval. For a half-open validity rule `0 <= u < width`, a valid point can lie beyond the default right image edge `width-0.5`; do not silently change the scientific validity rule or clamp coordinates to hide a framing error. Check both x/y limits, axis direction, autoscale state, actual scatter offsets and the image-corner transform into the final axes rectangle. When panels are meant to match, compare their drawn viewport sizes/scales as well. A correct image extent, equal aspect or a test of an image helper without the later scatter is insufficient.

Demonstrate sensitivity with a disposable fault that re-enables autoscale: the extent may still pass, but the final viewport assertion must fail before export acceptance. Preserve the failed artifact/receipt separately. Inspect the saved affected card at final resolution; reuse previously inspected, hash-identical outputs for unaffected cards when their acceptance remains bound. Do not rerun experiments merely because a viewport assertion was added.

## Test data meaning and resource ownership

When several panels share a quantitative colorbar, the same numeric value must map to the same color in every panel and the bar under the declared scale. Use differing panel value ranges with an overlapping literal value to expose unintended per-panel normalization. Fix the shared range from the contract, not each panel's extrema; genuinely different scales need explicit separate labels. Check the final artists and saved output. This check complements coordinate/identity acceptance and does not justify a new general-purpose validator.

Derive expected panel/projection identities from the contract, independently of the renderer's indexing logic. For each required row/column/method/projection, check both x and y ranges and the plotted coordinates against the corresponding input data. Use a small asymmetric fixture that would fail if rows/columns or coordinate components were swapped; for scatter plots inspect the actual offsets, not just axis labels or xlim. Add the missing assertion to the existing regression where possible. These semantic checks complement the frozen-input public render; neither substitutes for the other.

When visible labels must preserve raw numeric coordinates, specify that independently from marker placement and receipt values. Fixed decimal formatting must not silently round an accepted fractional input. Exercise values beyond the formatter's precision and compare the actual emitted label against an independent contract-derived expectation, including its final fit. Numeric round-trip preservation and exact original decimal spelling are different requirements; retain the original representation when the latter is required. If display rounding is authorized, declare its precision instead. A correct raw value in JSON does not prove that the displayed text retains it, and layout pressure is not permission to discard digits.

Check that fault fixtures reach the intended failure boundary:

- Freeze expected bytes/hash before modifying the source, and ensure the replacement differs. Overwriting the same path and then deriving its expected hash from the replacement does not test drift.
- Match the real callable signature, including positional arguments. Scoped wrappers should accept and forward the actual arguments; use `autospec` when useful. Assert the intended exception and reason through the public entrypoint, so an unrelated `TypeError` or `FileExistsError` cannot count as successful rejection.
- Give independent fault cases separate owned output directories. Assert the contract's failure result, such as no successful receipt; do not require an absent directory/PNG when diagnostic output is permitted, or recursively delete outputs to force that assertion.
- Use the library's real cleanup API, such as Matplotlib's [`plt.close(fig)`](https://matplotlib.org/stable/api/_as_gen/matplotlib.pyplot.close.html), rather than assuming a `Figure.close()` method. Cleanup must preserve unrelated Figures and must not mask the injected failure.

Separate fixture defects from defects in the renderer or its acceptance gate. Correct fixtures in the existing test framework, retain the original failed worker evidence, and rerun the affected checks; a fixture repair alone does not establish product acceptance.

When a renderer acquires a Figure or another resource, cleanup responsibility starts at acquisition, including layout or artist setup before the builder returns. A caller's `try/finally` entered only after `build_figure()` succeeds cannot clean up a partially built Figure. The builder must release what it owns on construction failure, and the receiving caller must release it after successful handoff, including save failures. Prefer closing the specific owned Figure over process-wide `close('all')`.

Test distinct failure boundaries that the implementation actually has: for a builder plus exporter, inject one failure after acquisition but before handoff (for example layout) and one during export. Compare the open-resource set before and after, preserving a pre-existing unrelated Figure when applicable. A save-only injection does not prove construction cleanup; no fixed test count or exhaustive injection at every plotting call is required.

For multiple owned images, buffers or files, track each acquired object's identity and cleanup obligation. Enter cleanup scope as each acquisition succeeds: a second crop/image creation or resize can fail before a later shared `try` begins. In the existing public failure test, fail a later acquisition after an earlier object exists and verify every already-owned object is released, while caller-owned objects remain usable. Observers should call through to real cleanup and establish closure per object; a global `close_mock.called` or aggregate call count can be satisfied by closing only the canvas while leaking crops. Retain the original exception and verify export failure cleanup separately when it has a distinct ownership path.

## Test the final export

### Separate numeric coverage from visual coverage

An exhaustive numeric audit can verify values while saved labels remain crowded or a legend covers data. Inspect the final saved images for those failures even when all numeric checks pass. Bind the receipt to the accepted report version and image hashes, distinguishing whole-set contact-sheet coverage, explicitly listed full-resolution inspections and any separate all-record numeric audit. Contact sheets can support overview/layout coverage; they do not establish full-resolution text readability for every card. Saved-image inspection also does not establish browser UI behavior.

Derive the required coverage from the original contract and concrete visual risks. State why any sampled full-resolution set is sufficient for that scope and retain uninspected detail as a limit; do not silently reduce required full coverage or retroactively claim it was done. A previous all-card overview plus selected key-card inspection is not a universal sample size or a reason to require every future card at full resolution.

After a layout fix, inspect the affected final images and bind their new hashes before acceptance. Reuse unchanged image inspections only with matching bytes and scope; unchanged numeric/source evidence can be reused separately when its dependencies still match. Numeric PASS cannot waive an unresolved required visual defect. Preserve interim defects and their resolution without changing scientific results or rerunning frozen experiments for a presentation-only correction. Use the existing review and any authorized visual helper under its named lifecycle coordinator; no extra agent stage is required.

### Derive coverage from the exported scene

When the contract requires a complete annotation inventory, discover the in-scope visible objects from the actual exporter scene after construction/layout. Do not treat a private list populated by a label helper as the observed inventory: an additional visible object can bypass that helper and therefore escape both inventory and bbox checks. In a renderer whose contract uses Figure-level text, enumerate visible `fig.texts`; this is not a universal inventory of every axes label, legend or annotation. Other renderers must include their actual in-scope artist containers or scene nodes. Define permitted object types, visibility and optional annotations from the contract rather than banning all extra content globally.

Map the complete display contract to actual scene observations and independent expected values before implementation/review. Review these together in the existing visual acceptance check, so a repair covers related ways required content can disappear or change meaning:

- **Visibility and containers:** check required artists and their owning containers, including `Axes.get_visible()`; a visible child can still disappear inside hidden axes. Keep this separate from `ax.axison`: [axis-off controls decorations](https://matplotlib.org/stable/api/_as_gen/matplotlib.axes.Axes.set_axis_off.html). For a contract requiring no axes text, inspect left/center/right titles and both axis labels as well; `fig.texts` cannot cover these.
- **Appearance and geometry:** inspect required image/scatter visibility, effective opacity, marker size and shape/path, coordinate transforms and stacking relative to the image, as well as face/edge colors, linewidth and path effects. Derive expected values from the task and independent fixture, not the renderer's own constants or receipt. Empty faces, white edges and a black halo are a neutral-ring example, not a universal style. Validate private attribute access, such as path-effect `_gc`, against the target library version.
- **Final clipping:** after final layout/draw, inspect clip enablement, path and box for each required image/overlay in the same display coordinates. When the contract requires clipping enabled, no custom path and a full rectangular axes clip box, require all three; a matching custom-path bbox does not satisfy the no-custom-path rule. Authorized custom crops need their own expected region. `clip_on=True` or `clip_path=None` alone is insufficient: Matplotlib can [store a rectangular clip in the box](https://matplotlib.org/stable/api/_as_gen/matplotlib.artist.Artist.set_clip_path.html) while leaving the path `None`.

Choose faults that preserve a weak oracle's summaries while violating the actual contract. A circle can share the axes bounding box while clipping its corners. A tiny plus or reordered path can retain vertex counts, positive extent or sorted absolute-coordinate distributions while changing size or connectivity. For a prescribed marker representation, derive its normalized reference path independently from the declared marker specification; compare ordered vertices and path codes, size transforms, and both path and offset transforms. Check the library's normalization at the target version/DPI, and permit alternative representations only when the contract establishes their equivalence. Positive size, a shape name or a coordinate histogram is insufficient.

For transformed floating-point bounds, require finite, correctly shaped values and an explicit tolerance in the compared units. With a fixed pixel budget, use `rtol=0` and a justified small absolute pixel tolerance; [NumPy's comparison rule](https://numpy.org/doc/stable/reference/generated/numpy.allclose.html) otherwise adds a magnitude-dependent allowance. The observed card used `atol=1e-7` pixels; validate the target backend/DPI rather than copying that threshold universally. Retain exact checks for hashes or source values whose contract requires exact identity: unchanged endpoint coordinates should not acquire default `allclose` relative tolerance. Exercise a small forbidden drift that such a tolerance would accept. Keep the original exact-equality failure and the corrected candidate separate.

Observe these requirements independently in tests and exercise representative failures through the public export path, including a hidden parent, altered marker and changed clipping where applicable. Both a custom path and a shrunken/empty clip box can hide content. Reuse existing tests/subcases without a fixed count or new model stage; each case must fail for its intended reason before a success receipt. Property checks still need saved-output inspection for actual visibility and occlusion.

Keep expected content independent of the discovered scene. For an exact text inventory, compare multiplicities (for example with `Counter`), not only sets or “each expected string is present”; duplicate or unexpected visible text must not disappear from the comparison. If placement or role matters, also bind labels to their declared panel/role: a text multiset alone cannot distinguish swapped panels. Use the same discovered objects for inventory, finite bbox/containment, required separation/no-overlay checks and the audit receipt. A receipt assembled from the same incomplete private registry does not establish coverage. Preserve the final export settings and prevent later scene changes from escaping the gate.

Add a bounded fault through the real public rendering/export entrypoint: inject a visible annotation into the final scene without adding it to the renderer's private registry, at a location forbidden by the contract when testing no-overlay behavior. The real gate must reject for the intended inventory/layout reason and must not emit a successful receipt. Retain ordinary valid-output coverage. Directly testing a private checker or injecting through the registration helper does not establish detection of an unregistered object. Add this to the existing declared test command; no separate model stage or business experiment is required.

If review finds this bypass after an earlier repair, that candidate still needs changes even when its ordinary exports look correct. A revised gate may leave all valid PNGs byte-identical; those hashes can support reuse of the corresponding image inspection, but cannot prove the new rejection path. Bind the fault-case result and refreshed affected acceptance/review to the revised source, and retain prior failed findings. Do not claim a pending review has passed or rerun frozen scientific computations merely to validate this gate.

Use the real plotting library, renderer, export DPI and final layout settings, then inspect the saved files. Synthetic tests complement actual-data display acceptance; they do not replace it. For the observed clipping failure, add one useful regression over the complete requested output set:

1. Draw the figure after layout has finished, at the export DPI. Measure each required legend (including its text/handles), title, heading and axis label against the actual exported canvas. Assert finite bounds and complete containment; a negative anchor is not inherently wrong, but the resulting exported content must fit.
2. Where the design reserves separate margins, assert that the legend does not overlap panel content/tick labels and that figure headings do not collide with panel titles. Test the stated design, not a universal ban on intentional overlays.
3. Save using the same settings inspected by the assertions. `bbox_inches='tight'`, alternate DPI, a different backend or later layout changes can change the output geometry; a pre-save `fig.bbox` assertion alone is then insufficient. Reopen the output and verify dimensions, and use export-aware measurement plus visual inspection if the crop/backend differs. Do not silently switch to tight cropping when output dimensions are part of the contract.
4. View the actual saved artifacts: full-set/contact-sheet review plus full-resolution inspection of each layout class and dense labels. Validate Chinese terms, glyph rendering, branch/projection mapping, required capture dates/source labels, index links and captions. Inspect actual glyphs as well as text extents: missing-glyph warnings that produce boxes or unreadable required text fail acceptance, even when all bounding boxes fit. Use an available font that covers the required text or a language alternative permitted by the task, then verify the saved output. Do not silently label unreadable text cosmetic, suppress the warning to obtain PASS, install fonts without scope, or require English labels universally. Other warnings need an assessment of their actual impact, not a blanket warning-as-error rule. A pixel boundary test cannot prove semantic correctness, readability or scientific validity.

For the separation check, map the actual required text roles to explicit object pairs: a figure title and subtitle, a legend and subplot title, or other neighboring labels declared separate by this layout. Containment in the canvas does not establish separation between them. Use the discovered scene inventory and final export renderer/DPI to measure those pairs, with any gap derived from the design rather than a universal pixel threshold; preserve intentional overlays. When an old layout exposed a collision, inject that placement through the public export path in an owned fixture, keep the objects inside the canvas, and require rejection for the intended overlap before a successful receipt. Retain a valid-export case. Directly testing a private bbox helper, or testing only out-of-canvas text, does not demonstrate that this public collision is rejected. Reuse the existing declared test command and frozen inputs; no scientific rerun is needed.

Do not inflate test counts, automatically add review rounds or replace the project framework. Keep the original regression command and add the smallest check that detects the demonstrated defect. A defect found after apply/test means changes requested; fix in a fresh candidate and bind a new test/review receipt. A worker with model/tool/final evidence but failed real-input or visual acceptance has an implementation/acceptance failure; do not classify that as zero-output transport failure. An Astra takeover after a failed repair does not finalize that failed worker run.

## Reusable bounded examples

For a renderer combining images, coordinates and metadata, adapt [render_reference.py](../assets/visual-layout/render_reference.py) and its independent [asymmetric.json](../assets/visual-layout/asymmetric.json) fixture into the declared project files and existing tests. It demonstrates one Figure-owning scope spanning population/layout/save and success; before-load/consumed-byte/final input hashes; distinct source/output identities and raw/kept/display counts; complete unsampled layer bounds; XY/XZ offsets and both limits; and image aspect preservation. Literal fixture expectations deliberately differ across names, counts, axes and layers. They are not generated by the implementation under test. Its explicit keep/sample indices are synthetic setup, not a scientific filtering policy, camera model or registration implementation.

The same example includes an unavailable-result card with long title/body, a real PNG export, and separate title/body clipping failures that stop saving. Its source check rejects another file with the same basename and bytes at a different full path. Supply `expected_path` from the trusted source plan, independently of the attempted read path; the local example uses canonical paths, while project adapters must also enforce their declared frozen hashes and host mapping. Existing hash-change tests demonstrate that no successful receipt is returned after input drift. A well-rendered unavailable card is a presentation success, not success of the missing scientific result.

The shared [check_layout.py](../assets/visual-layout/check_layout.py) measures drawn artists at final DPI and accepts explicit `separate_pairs` and a `gap_px` from the layout contract. The reference checks metadata-versus-legend and an upper-panel xlabel versus the lower-panel title with a two-pixel gap. Controlled collisions first pass containment, then fail separation: a containment-only `layout_pass` is not visual acceptance. Adapt the actual pair inventory and gap to the target layout; the example does not discover every possible collision. It uses the returned `_update_ticks()` list, not all locator ticks; this private Matplotlib API needs checking in the target version. The fixture also distinguishes half-open pixel validity (`0 <= u < width`) from continuous layout bbox containment, where touching a canvas edge is not automatically a domain error. Its fractional right/bottom-edge point remains in the scatter offsets while the fixed image viewport stays unchanged; a deliberately re-enabled autoscale fails the drawn-viewport check even though image extent remains correct.

Run only the relevant example with an existing Matplotlib environment:

```text
/absolute/existing/python assets/visual-layout/render_reference.py -v
/absolute/existing/python assets/visual-layout/check_layout.py -v
```

The second retains the earlier eleven-image layout example and clipping/title-collision regressions. Both use only synthetic data, temporary outputs and isolated Matplotlib caches, install no dependency and remain separate from the helper's core suite. Missing dependencies are NOT VERIFIED, not a skipped PASS. These are adaptation aids, not an additional mandatory model/test stage: use the smallest useful assertions with real inputs and public exports, and retain actual-artifact inspection. Neither example establishes scientific validity, business semantics, or project acceptance. Failed example runs can leave an output inside their managed temporary directory but cannot produce a successful receipt.
